## Actual frontend integration

- `/staff/subscription` preserves Core/Complete comparison, approved display catalog, all three modes and deterministic expandable HON guidance. Live operational prices/allowance metadata and founder pool counts come only from returned B5 offers. Another plan is an informational comparison, never a browser-authorized upgrade. Backend command rechecks final eligibility, inventory and permission; an offer listing is not a founder reservation.
- Fixed `GET /api/v1/staff/current-reporting-school` resolves one candidate school. It does not confer billing authority. B5 independently verifies `billing.hon.purchase` through `GET /api/v1/schools/:schoolId/hon-plan` and each checkout command. Ambiguous/multi-school contexts fail closed, without manual/query IDs or HQ/family fallback. Responses bind school, organization, subscription and checkout identities and reject closed-contract drift.
- The explicit review/owner confirmation submits only `{offerId}` to `POST /api/v1/schools/:schoolId/hon-plan/checkout`, using B5's `saas-checkout-start` human-command header, same-origin fetch metadata, UUID idempotency key, no-store and no redirect following. Scope and immutable offer terms are reread before sending. Immediate in-memory locking prevents duplicate submission. Changed terms invalidate review. Unknown/provider outcomes require refresh and explicit same-input/key retry; no automatic POST retry. An unresolved CREATED checkout after a full page reload may require support because no browser persistence of command authority/key was added.
- The merged service returns `providerCall` in addition to the shared closed `SaasCheckoutReceipt`. The frontend validates those three merged response fields, then uses the canonical receipt validator. No backend contract changes were made.
- Only a returned OPEN TEST-mode STRIPE checkout with a test-session ID and exact HTTPS `checkout.stripe.com` destination exposes a hosted handoff link. HON never collects card data. Simulator URLs are not navigated or represented as real Stripe sessions. No provider program is enabled from this UI.
- B5's existing hosted return path `/schools/:schoolId/hon-plan` is now session-protected. Path/query school, checkout and result values are ignored. Current server-resolved account/payment facts are fetched independently, so a forged success/cancel URL proves neither payment nor cancellation.
- Actual subscription, paid/attested/disputed/refunded/past-due distinctions, current service period, founder offer/reservation reference and checkout CREATED/OPEN/COMPLETED/FAILED/CANCELLED/EXPIRED/PAID_NEEDS_REVIEW states are shown from the backend. Verified test payment shows **Pending Account Activation**, with the current provisioned tier separate. No frontend entitlement mutation or claim that paying activated features.
- Independently authorized B3 `GET /api/v1/schools/:schoolId/ai-credits` supplies actual allowance, consumed, reserved and remaining values. No browser totals, grant or planning allowance substitution. Permission/identity/subscription mismatches clear balances. Aborted/stale responses cannot restore old records after refresh.
- Loading/empty/denied/error/changed/uncertain states clear old facts. A returned invoice ID is labeled as a reference; school invoice details/download remain unavailable because merged B2/B5 exposes only HQ detail reads. No family-billing/HQ endpoint fallback or fake receipt link.
